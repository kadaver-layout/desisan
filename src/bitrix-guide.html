DESISAN: руководство интегратора Битрикс

Передача от 8 ноября 2026. Документ описывает текущие исходники и реальные точки подключения. В репозитории — статическая вёрстка и демонстрация состояний. Серверные обработчики, инфоблоки, обмен с 1С, оплата, доставка и рассылка не реализованы.

Сборка · Шаблоны · JavaScript · Контракты · Сервер · Приёмка

1. Сборка и ресурсы

npm ci
npx gulp build
npx gulp build --prod

Нужен Node.js 22.13+. Версии зафиксированы package-lock.json. npm run dev/prod запускают сервер с наблюдением; для разовой передачи используйте gulp build. Полная сборка очищает dist: ручные правки и PHP там не хранить. Логику сборки и зависимости для интеграции менять не требуется.

Подключить один раз dist/assets/css/main.css, необходимые css/libs и dist/assets/js/app.js. Перенести img/fonts/video с сохранением относительных путей либо согласованно заменить пути шаблоном сайта. assets/js/raw и dist/html — копии исходников, отдельно на страницу не подключаются. В development есть source maps; production не минифицирует CSS, JS сохраняет читаемое форматирование.

3. Жизненный цикл JavaScript

Единственный вход Webpack — src/assets/js/app.js. Задайте window.DesisanIntegrations до подключения app.js: часть загрузок начинается сразу на DOMContentLoaded. Все адаптеры асинхронные. URL, авторизацию, CSRF и транспорт определяет серверный проект. Ответ адаптера — непосредственно объект полезных данных без обёртки response.data.

// Схема, не готовый HTTP-клиент. projectApi реализует ваш проект.
window.DesisanIntegrations = {
  search: (query, { signal }) => projectApi.search(query, { signal }),
  addToCart: (productId, { attemptId }) =>
    projectApi.addToCart({ productId, attemptId }),
  createOrder: (values, { attemptId }) =>
    projectApi.createOrder(values, { attemptId }),
  getOrderStatus: ({ attemptId }) =>
    projectApi.getOrderStatus({ attemptId })
};
// Дополните остальными методами ниже; фиктивные успехи не возвращать.

Не затирайте ранее заданные методы новым объектом. Некорректный ответ/ошибку HTTP преобразуйте в отклонённый Promise, если контракт не предусматривает конкретный статус отказа.

Универсального публичного init/destroy для AJAX-компонентов нет. Повторный запуск app.js на прежнем DOM дублирует обработчики. Без доработки жизненного цикла используйте обычную серверную навигацию. Для AJAX отдельно реализуйте снятие слушателей/наблюдателей и инициализацию нового корня. Каталог, поиск и новости хранят снимок карточек первоначального DOM: простой вставки HTML недостаточно.
МодульОбласть ответственности

4. Контракты адаптеров

Все методы возвращают Promise. Знак ? означает необязательное поле. Денежные значения — числа в рублях, без знака валюты. Сервер является источником цены, наличия, прав и итогов.

Метод и аргументыОтвет и поведение
search(query, { signal })Массив { title, url }. Подсказки от двух символов, задержка 300 мс, до пяти результатов. Передайте AbortSignal транспорту, устаревшие ответы отменяются. Без адаптера — поиск по демонстрационному DOM.
addToCart(productId, { attemptId }){ count, title? }; count — полное количество единиц всей корзины. Альтернативы: { status: 'price-changed', price } или { status: 'unavailable' }. Новая цена требует повторного нажатия. Без адаптера успех и счётчик не имитируются.
setCity(city)Подтверждение сохранения (void). После успеха событие desisan:city-changed с detail.city; интегратор обновляет доставку/цены.
beforeCartLoad(), beforeCheckoutLoad()Ожидание без используемого возвращаемого значения. Раскрывается заранее собранный template; для живого сайта заменить эту ветку актуальным серверным HTML.
updateCartItem({ id, quantity }){ quantity?, price?, oldPrice? }. Цены одной единицы, количество подтверждённое. Ошибка восстанавливает старое количество, повтор сохраняет желаемое.
removeCartItem({ id })Подтверждение удаления (void). При отклонении строка остаётся. Без адаптера изменение/удаление локальные, не сохраняют корзину.
validateCart(){ valid?, changed?, message?, items?: [{ id, price?, oldPrice?, available? }] }. Изменения останавливают переход, недоступная позиция блокирует оформление.
validateCheckout(FormData){ valid?, changed?, available?, message?, subtotal?, discount?, total?, items?: [{ id, price }] }. discount положительный. Изменения сохраняют черновик и требуют нового подтверждения, createOrder автоматически не вызывается.
createOrder(FormData, { attemptId }), getOrderStatus({ attemptId }){ status: 'created', url } либо { status: 'not-created' }. Потеря ответа вызывает проверку той же попытки, не повтор создания. Неизвестный результат сохраняет блокировку.
getOrderResult(){ html }, доверенный серверный фрагмент с main.order-success. Проверять доступ к текущему заказу. Повтор только читает, не создаёт заказ и не очищает корзину. DOMParser не очищает вредоносный HTML.
sendContactMessage(FormData, { attemptId }), getContactMessageStatus({ attemptId }){ status: 'sent' | 'not-sent' }. sent означает принятие сервером, не гарантию доставки. Неизвестный результат блокирует повтор.
sendProductReview(FormData, { attemptId }){ status: 'sent' } либо { status: 'error', errors?: { name?, rating?, review? } }. Успех — подтверждение модерации; список и рейтинг сразу не меняются. Неизменённый отзыв повторяется с тем же ключом.
beforeCatalogLoad({ filters, offset, limit }), beforeSearchResultsLoad({ query, offset, limit }), beforeNewsLoad({ offset, limit })Ожидание раскрытия имеющихся карточек. Ответ не вставляется в DOM. Для серверной пагинации доработать запрос, снимок карточек и счётчики. Отказ оставляет уже показанное и даёт повтор.
beforeNewsArticleLoad()Ожидание перед повтором. Сейчас переход на news-article-1.html — демонстрация; заменить реальным URL нужной статьи.

5. Что должен сделать серверный разработчик

Идентификаторы, маршруты и списки

data-add-to-cart получает реальный ID товара/предложения. В cart.js идентификатор пока читается из href первой ссылки строки: заменить чтения update/remove и сопоставление validateCart единым ID строки корзины. URL товара не различает несколько строк одного SKU с разными свойствами. Порядковые data-checkout-item-id заменить реальными ID, согласованными с validateCheckout.

Настроить action поиска и ссылки корзины через серверные данные. index11.html и index3.html — статические демонстрационные маршруты. /catalog/…, /privacy/… и другие ссылки требуют реальных роутов. Параметры каталога min/max, discount=1, gender/type через запятую, sort и shown — демонстрационная схема, согласовать с серверным фильтром. Сервер считает всю выдачу и счётчики, а не только уже загруженные карточки.

Проверить доступность карточек и рекомендации, исключение текущего SKU/дубли, пустые блоки, длинные названия и отсутствие фото. Не все старые демонстрационные массивы гарантируют фильтрацию available=true. Авторизованные точные остатки выводить по серверным правам; productDetail.isAuthenticated — только демонстрационный флаг.

Поля форм

ФормаПоля и особенности
Оформлениеcity, delivery, name, email, phone, address, comment, payment, privacy, newsletter. Последние согласия находятся вне form, связаны через form="checkout-form". Использовать FormData(form), не только вложенные input. При самовывозе address disabled и не отправляется. Значения delivery/payment текстовые: при переходе на коды изменить и сравнение «Самовывоз» в JS. newsletter необязателен.
Контактыname до 80, email до 254, message до 2000, обязательное privacy. Сервер повторяет проверки и фиксирует согласие.
Отзывname 2–80, rating обязательно, review 20–2000, consent обязательно. Добавить ID товара из проверенного контекста или hidden-поля с серверной проверкой.

FormData снимать до блокировки полей: disabled не отправляются. Чекбокс без value передаёт on; отсутствие поля не означает согласия. Сервер повторяет проверку обязательности, формата, длины, доступности и согласий. Для детальных серверных ошибок полей оформления понадобится расширение текущего контракта: сейчас выводится общая ошибка.

Идемпотентность и неизвестный результат

Сервер атомарно связывает attemptId с владельцем и результатом операции. Сетевой повтор добавления или неизменённого отзыва использует тот же ключ. getOrderStatus проверяет ту же попытку createOrder. not-created/not-sent допустимы только при достоверном отсутствии результата: обрыв сети не является отказом. Неизвестный статус не должен запускать новую покупку.

Ключи текущей вёрстки живут в памяти страницы. Реализовать восстановление незавершённой операции после reload через сервер/сессию, сценарий поддержки и проверку статуса. Создание заказа, резервирование, очистка корзины выполняются сервером; страница успеха их не повторяет. После операций корзины синхронизировать общий счётчик/итоги с сервером, не полагаться на локальный пересчёт.

Безопасность, кеш и персональные данные

Транспорт проверяет сессию/CSRF, права, владельца заказа, частоту запросов; валидирует ID, цены, остатки и итог независимо от DOM. Экранировать значения при HTML-выводе, проверять протоколы/адреса URL подсказок, переходов и медиа. Не допускать открытых перенаправлений и чужого заказа из общего кеша. Секреты не хранить в JS. Персональные корзины, цены и результат заказа кешировать с учётом пользователя.

SEO-метаданные, canonical, robots, защищённые ссылки, юридические документы и настоящий HTTP 404 обеспечивает серверный проект.

Город, cookie и медиа

desisan_consent, desisan_city, desisan_city_confirmed сохраняются на год; закрытие cookie без принятия — в sessionStorage. Баннер сам не блокирует аналитику: интегратор подключает её согласно согласию. Геолокация не имитируется: site.detectedCity задаёт сервер либо отправляется desisan:geo-detected с detail: { city }.

Карта контактов — статическое изображение, не API карт. Адрес самовывоза и реальные координаты требуют данных. Галерея принимает фото { src, alt } и видео { type: 'video', src, poster?, alt? }; сохранять порядок миниатюр и просмотрщика. Текстовое видео использует data-video-src и внутренние data-video-player/error/loading/retry. Без источника блок не выводить. Реальный видеоролик для проверки не предоставлен.

Письма

layouts/email-order.html и includes/email-transaction.html — табличный HTML с inline-стилями, без app.js сайта. Восемь email-*.html — образцы, не рассылка. Формировать из сохранённого заказа/серверных событий, экранировать данные, удалять пустые необязательные блоки и нулевую скидку.

Заменить относительный логотип на HTTPS/CID, контакты и token=example на реальные данные/одноразовый токен. Добавить защищённую ссылку менеджера, отслеживание при наличии URL перевозчика, реальный адрес получения. Не отправлять тестовые токены. Проверка реальных почтовых клиентов и доставки не выполнялась.

6. Слайдеры Splide 4.1.4

Все ленты, баннеры и галереи управляются установленным @splidejs/splide через npm-импорт в sliders.js. CDN и повторное подключение Splide не нужны. CSS библиотеки уже подключён в main.sass, оформление проекта — sliders.sass. Старые обработчики scrollBy, определения индекса по scrollLeft и свайпов удалены. Панорамирование увеличенной фотографии и загрузка медиа остаются отдельным кодом.

Вид и HTML-хукиПоведение
hero.html: data-hero → data-hero-track → .hero__slide; data-hero-prev/nextОдин баннер на экран, движение Splide, без autoplay и циклического перехода. Кнопки блокируются на краях. Один кадр не требует стрелок.
category-rail.html / product-rail.html: data-rail → data-rail-track → li; data-rail-prev/nextС 1280 — слайдер фиксированной ширины карточки, шаг одна карточка, остановка на конце без пустого хвоста. С 1920 размеры увеличиваются. Ниже 1280 Splide уничтожается через breakpoint destroy, остаётся сетка макета; при возврате на desktop библиотека восстанавливает экземпляр.
product-gallery.html: data-product-gallery → data-gallery-track → .product-gallery__slide; data-gallery-thumbs → data-gallery-thumbОсновной кадр и миниатюры — два синхронизированных Splide. Фотокнопка открывает dialog, video имеет нативные controls. Счётчик и aria-pressed следуют индексу библиотеки. На планшете миниатюры скрыты. Порядок и количество кадров должны совпадать.

В каждом кадре свои фото/видео, ошибка и повтор; ID zoom уникальны по индексу. При открытии dialog вызывается refresh для вычисления размеров. Стрелки клавиатуры работают глобально только пока dialog открыт. Escape и фокус обслуживает общий менеджер диалогов.

Галереи используют rewind вместо loop: переход с последнего кадра на первый без клонирования DOM и дублирования ID/видео. При смене кадра видео останавливаются, увеличение сбрасывается. В увеличенном виде Drag полноэкранного Splide отключается, чтобы движение изображения не перелистывало кадры. При закрытии просмотрщика видео ставится на паузу.

API и обновление компонента в Битрикс

// Внутри исходного ES-модуля проекта, не в inline-скрипте PHP:
import { initRails, initHero } from './sliders.js';
// После вставки НОВОГО HTML (для этих двух функций есть защита от дублей):
initRails();
initHero();

// Экземпляр находится на исходном списке:
const list = document.querySelector('[data-rail-track]');
const slider = list?.desisanSlider;
slider?.go('>');        // следующий кадр
slider?.go(0);          // первый кадр
slider?.refresh();      // пересчёт после изменения размеров/готового DOM
slider?.destroy(true);  // перед удалением старого компонента

Не вставлять inline-вызовы этих импортов: изменения подключаются через существующую сборку app.js. Для новой галереи вызвать initProductGallery из product.js после вставки всех её частей; функция защищена от повторной инициализации старого корня. Галерея рассчитана на одну страницу товара и связанный #product-viewer. При AJAX заменять их вместе и уничтожать все три экземпляра со старых списков, затем удалять старый DOM и инициализировать новый. Простого refresh недостаточно при изменении состава медиа: обработчики ошибок и связь кадров создаются при инициализации.

Если обновляются карточки внутри существующей ленты, предпочтительно использовать add/remove Splide с готовой серверной разметкой. При прямой вставке добавить новым элементам splide__slide и вызвать refresh; обновление кнопок покупки/других компонентов требует отдельной инициализации, весь app.js повторно запускать нельзя. destroy(true) использовать при окончательном удалении: breakpoint destroy без true обслуживает сама библиотека.

Никаких новых зависимостей для перехода не добавлено. Для отключения анимации учитывается prefers-reduced-motion. Не добавлять autoplay, loop, новые стрелки или точки без соответствующего поведения макета.

7. Последовательность интеграции и приёмка

  1. Собрать проект, перенести общий шаблон, ресурсы, метаданные; проверить пути, шрифты и единственное подключение JS/CSS.
  2. Вывести сервером страницы, меню, товары, списки и формы; заменить все тестовые ID/URL. Убрать принудительные data-page-preview и демонстрационные состояния из боевых страниц.
  3. Подключить подсказки, город, операции корзины и серверную синхронизацию счётчика.
  4. Подключить предварительную проверку, создание, идемпотентность и защищённый результат заказа. Проверить смену цены/остатка между проверкой и созданием.
  5. Подключить контакты, отзывы и письма. Проверить задержку, отказ, потерю ответа после принятия, повтор и reload.
  6. Проверить серверную пагинацию, фильтры, историю, общий счётчик на объёме больше одной порции.
  7. Проверить клавиатуру, фокус/Escape, меню/назад, все размеры макета и промежуточные ширины, отсутствие переполнений и ошибок JS.
  8. Провести реальные тестовые отправки писем, проверить доступ к заказу и HTTP 404.

browser-qa.cjs и browser-flow-qa.cjs требуют внешней временной установки Playwright, не являются переносимым npm test. Для другой среды адаптировать путь либо использовать собственный прогон; новые зависимости требуют согласования. Сборка не доказывает визуальное совпадение или готовность Битрикс.

Незавершённые части исходной проверки: полный финальный визуальный аудит; пагинация/ошибки списка отзывов; все варианты длинных характеристик и авторизованного остатка; правила related/recommendations; реальные видео, touch-жесты, почтовые клиенты. Руководство не объявляет эти части проверенными.
