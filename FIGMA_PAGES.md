сверстанным, пока не проверены все предусмотренные разрешения и сценарии.

покрыты не все состояния; `сверстано, проверить` — все состояния перенесены,
нужна визуальная проверка; `готово` — сверено с Figma и собрано.

## Обязательная проверка каждой страницы

- Комментарии для разработки и библиотека компонентов прочитаны.
- Все состояния из узла перенесены в Nunjucks-шаблоны: пустые, ошибки,
  загрузка, заполненные и длинные данные, если предусмотрены.
- Все разрешения из макета и промежуточные ширины проверены.
- Серверные сценарии отмечены точкой интеграции Битрикс; успешные ответы не
  имитируются клиентским кодом.
- Сборка проходит, отсутствуют горизонтальный скролл, обрезания и ошибки JS.

## План работ

1. Открыть актуальный файл Figma и сначала изучить библиотеку `1:70771`:
   токены, компоненты, варианты, состояния, доступность и комментарии.
2. Последовательно провести аудит узлов `0:1`, `1:6177`, `1:17814`,
   `1:10017`, `1:33409`, `1:45266`, `1:55421`, `1:56505`, `1:57954`,
   `1:63484`, `1:69112`, `1:70428`. Для каждого заполнить имя страницы,
   разрешения, все состояния и список компонентов в таблице выше.
3. Сопоставить аудит с существующими `src/index*.html`, include-файлами,
   данными и Sass. Отдельно отметить уже реализованное, расхождения и
   отсутствующие состояния.
4. Дорабатывать страницы строго по порядку реестра: сначала общие компоненты,
   затем шаблон, данные, Sass и только необходимый JS для интерактивных
   состояний. Серверные операции оставлять точками интеграции Битрикс.
5. После каждой страницы: development-сборка, проверка всех размеров макета,
   промежуточных ширин, клавиатуры и состояний; затем обновление статуса в
   таблице.
6. Завершать страницу только после переноса всех её состояний. Статус
   `готово` выставляется после визуальной сверки, а не после одной сборки.
