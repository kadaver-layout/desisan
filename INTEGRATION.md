# Интеграция шаблонов DESISAN

Основная разметка собирается Nunjucks на этапе Gulp. В Битрикс переносится
HTML шаблонов из src/html/includes; страницы расширяют layouts/default.html.
В ходе текущей проверки настройки сборки и зависимости проекта не менялись.
Playwright для локальной проверки установлен вне проекта, во временной папке.

## Данные

src/data/data.json содержит демонстрационные категории, товары, ссылки и контакты.
Идентификаторы 101–108 и URL товаров — примеры для замены данными инфоблоков.
Товарные блоки показывают только available=true; пустой блок скрывается целиком.
Сортировку популярных и признак новинки нужно заполнять на стороне Битрикс/1С.
Логотип и VK пока текстовые, как в макете: официальные ассеты и URL сообщества
не предоставлены. Телефон и тексты требуют подтверждения заказчиком.

## Серверные адаптеры

До пользовательского действия можно определить window.DesisanIntegrations:

- search(query, { signal }): Promise<Array<{ title, url }>>. До пяти текстовых
  подсказок. Задержка 300 мс, запрос с двух символов, отмена устаревших ответов.
  На сервере фильтровать наличие, искать по названию/описанию с транслитерацией.
  Без адаптера работает поиск по демонстрационным карточкам главной.
- addToCart(productId, { attemptId }): Promise<{ count, title? }>. count — актуальное суммарное
  количество товаров из ответа корзины. Без адаптера успех не имитируется,
  счётчик не меняется, ошибка доступна через role=alert.
  Повтор сетевой ошибки использует тот же attemptId; сервер должен исключать дубли.
  Вместо успеха можно вернуть `{ status: 'price-changed', price }` или
  `{ status: 'unavailable' }`. Новая цена требует повторного нажатия.
- setCity(city): Promise<void>. При подключении дождаться серверного сохранения.
  После успешного выбора отправляется событие desisan:city-changed,
  event.detail.city содержит название. Интегратор обновляет расчёты доставки.

Пути action формы поиска и ссылки корзины берутся из data.json, а не из JS.
Адреса обработчиков, CSRF-токены и авторизацию задаёт интегратор.

Выбор города пока фильтрует список cities из JSON. Для полного справочника
заменить этот список данными Битрикс. IP-геолокация не имитируется:
site.detectedCity заполняет сервер или отправляет CustomEvent
desisan:geo-detected с detail: { city }. При отсутствии результата уведомления нет.

## Сохранение состояний

desisan_consent — согласие на cookie, год.
desisan_city и desisan_city_confirmed — город и его подтверждение, год.
Закрытие cookie-плашки без принятия сохраняется только в sessionStorage.
Сначала показывается cookie-плашка; уведомление о городе — после её закрытия.
Поиск, меню и выбор города используют native dialog, Esc и управление фокусом.
Системная кнопка «назад» закрывает мобильное меню.

## Принятые уточнения макета

Подробные описания отдельных состояний и библиотека приоритетнее старой общей
памятки, если они расходятся:
- Поиск — панель под неизменной шапкой, текстовые подсказки, от двух символов.
- Служебная полоса уезжает, основная строка закрепляется, без дублирования DOM.
- Cookie-плашка реализована по отдельному состоянию и библиотеке.
- Окно города полноэкранное ниже 1280 по библиотеке.
- Футер планшета — по фактическому компоненту библиотеки (логотип сверху,
  затем три группы); группы не являются аккордеонами.
- На мобильном для двух полных строк названия зарезервировано 32 px,
  цена не перекрывает название; длинный текст обрезается CSS, оставаясь в DOM.

## Корзина и оформление

Локальные пересчёт, удаление и ожидание показывают переходы состояний без перехода
на другую HTML-страницу. Отдельные страницы состояний сохранены для приёмки.
Исходное содержимое и резервные варианты собираются Nunjucks, не из браузерного JSON.

- `beforeCartLoad()` и `beforeCheckoutLoad()` — ожидание загрузки. Демонстрация
  показывает подготовленный HTML из template; при интеграции Битрикс подставляет
  актуальную разметку компонента вместо демонстрационного содержимого.
- `updateCartItem({ id, quantity })` возвращает `{ quantity?, price?, oldPrice? }`.
  В демонстрации id — ссылка позиции; интегратор заменяет её ID строки корзины.
  При отказе восстанавливается подтверждённое количество, повтор сохраняет запрос.
- `removeCartItem({ id })` подтверждает удаление; при ошибке строка остаётся.
- `validateCart()` возвращает `{ valid?, changed?, message?, items? }`.
  Элемент items: `{ id, price?, oldPrice?, available? }`. Изменение цены/состава
  останавливает переход. Недоступная позиция блокирует оформление до удаления.
- `validateCheckout(FormData)` до создания возвращает
  `{ valid?, changed?, available?, message?, subtotal?, discount?, total?, items? }`.
  Суммы — числа в рублях, discount — положительное число. Позиция items:
  `{ id, price }`; демонстрационные id соответствуют data-checkout-item-id.
  После изменений данные формы сохранены, создание не вызывается автоматически.
- `createOrder(FormData, { attemptId })` возвращает
  `{ status: 'created', url }` либо `{ status: 'not-created' }`.
  Потеря ответа переводит в проверку `getOrderStatus({ attemptId })` с тем же
  контрактом. Неизвестный статус сохраняет блокировку повторного создания.

Без createOrder заказ не создаётся, переход на успешный экран не имитируется.
`getOrderResult()` возвращает `{ html }`: серверный HTML `main.order-success` с
проверкой доступа к уже сохранённому заказу. Повтор не меняет текущий защищённый
URL и не вызывает создание заказа. Без адаптера прежнее сообщение сохраняется.
Страница результата принимает только уже сохранённый заказ; статус отправки письма
и реальный HTTP 404 обеспечивает сервер. Адрес самовывоза и координаты не заданы:
плейсхолдер макета сохранён, по нему карта не геокодируется.

## Формы, новости и поиск

- `sendContactMessage(FormData, { attemptId })` и
  `getContactMessageStatus({ attemptId })`: `{ status: 'sent' | 'not-sent' }`.
  Неизвестный результат не разрешает повторную отправку.
- `sendProductReview(FormData, { attemptId })`:
  `{ status: 'sent' }` или `{ status: 'error', errors?: { name?, rating?, review? } }`.
  Повтор неизменённого отзыва использует прежний attemptId для идемпотентности.
  Успех показывает подтверждение модерации; опубликованные отзывы и рейтинг
  немедленно не меняются. Черновик сохраняется до успеха на текущей странице.
- `beforeNewsLoad({ offset, limit })`, `beforeSearchResultsLoad({ query, offset,
  limit })` и `beforeCatalogLoad({ filters, offset, limit })` — точки ожидания
  подготовленной порции HTML. Отказ сохраняет уже показанные карточки и даёт повтор.
- `beforeNewsArticleLoad()` — повтор загрузки детальной новости.

Данные productDetail.images могут содержать фото `{ src, alt }` или видео
`{ type: 'video', src, poster?, alt? }`. Нужны реальные локальные файлы/URL из Битрикс;
фиктивный видеоролик не добавлен. Нативный video даёт паузу, звук, прогресс и полный
экран. Точные остатки выводятся только при productDetail.isAuthenticated=true.

В статической демонстрации поиск и корзина ведут на index11.html и index3.html.
Остальные маршруты `/catalog/...`, `/privacy/` и т. п. сохраняют точки подключения
Битрикс; это не проверенные серверные страницы статического файлового сервера.

## Письма

Восемь писем — самостоятельные табличные HTML с inline-стилями, PNG-логотипом,
скрытым прехедером, шириной до 600 px и базовыми полями 20 px. На desktop поля 40 px.
Данные приходят от сервера, значения экранируются. Отсутствующие необязательные
блоки удаляются целиком; пустые характеристики и нулевая скидка не выводятся.

Перед реальной отправкой заменить относительный путь логотипа абсолютным HTTPS
URL или CID, демонстрационные контакты и token=example — реальными данными.
Менеджеру нужна защищённая ссылка на заказ; сейчас для неё оставлен вид кнопки
без выдуманного адреса. У отправленного заказа ссылка отслеживания скрыта, пока
перевозчик не передаст URL. Бэкенд не должен отправлять письмо с тестовым токеном.
Проверка реальных Gmail/Outlook/Apple Mail/Mail.ru и доставка писем не выполнялись.

Изображения и SVG скачаны из Figma в src/assets/img. Все SVG используются
с их исходными размерами. Шрифты Onest Regular/Medium локальные.
